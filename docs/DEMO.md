# Демонстрация API

1. `docker compose up -d --build`; открыть `/docs`.
2. `POST /api/demo/load`; получить 69 строк. Повторить запрос и увидеть `idempotent_replay=true`.
3. `PATCH /api/accounts/main`, `/second`, `/market` с `{"own_confirmed":true}`. S01/S02 и S03/S04 становятся двумя событиями `OWN_TRANSFER`; расходы и доходы от них равны нулю.
4. `python backend/scripts/resolve_demo.py` применяет остальные решения через API. S07 становится долгом 300000 коп., S08/S09 закрывают его по 150000. Ресторан S10 делится на пять долей по 160000; четыре компенсации закрывают 640000 долга. S17 уменьшает расходы сентября на 420000, а ручная S19 добавляет 70000 расходов и уменьшает наличные.
5. `GET /api/analytics?from=2026-09-01&to=2026-09-30&grouping=week`: расходы 860000, доходы 2200000, net 1340000. Неразобранное входящее S15 — 50000. Недельные расходы: 650000, 270000, −240000, 130000, 50000.
6. `GET /api/accounts`: рассчитанные наличные 430000, изменение market +50000 без утверждения о балансе. `GET /api/receivables`: открытый остаток 0.
7. Классифицировать S15 как `INCOME`: доходы станут 2250000. Отменить решение по `decision_id`: вернутся 2200000 и неразобранные 50000.

Исходные и ожидаемые суммы перечислены в `backend/fixtures/expected-results.json`. Разбивка `demo-first.csv` и `demo-second.csv` перекрывается; после последовательного импорта должно остаться 69 уникальных банковских строк.
