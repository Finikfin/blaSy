# Решения и границы backend

- PostgreSQL 16 используется как единственное постоянное хранилище. Схема создаётся версиями SQL-миграций при старте API. Все финансовые команды исполняются внутри транзакции. Исходные банковские записи не редактируются; решения меняют только интерпретацию, связи и производные эффекты.
- Денежные величины хранятся `BIGINT` в копейках. Аналитика суммирует только эффекты подтверждённых событий. Неразобранные входящие и исходящие выводятся раздельно. Нулевой начальный остаток банковских счетов не предполагается.
- Канонический CSV и произвольные заголовки с явным сопоставлением поддерживаются. Для строк без ID счётчик одинаковых fingerprint сохраняет повторяющиеся реальные операции в одной выписке. Если две перекрывающиеся выписки без ID содержат неразличимые записи, происхождение невозможно восстановить точно; preview показывает дубли по счётчику.
- Автоматическая связь переводов требует подтверждения обеих своих карт и взаимных реквизитов. Если известен целевой свой счёт, исходящая сторона остаётся переводом с `coverage_status=missing_counterpart` до появления парной записи. Тип `transfer` сам по себе не подтверждает доход или расход.
- Возврат долга и компенсация всегда подтверждаются человеком. Сумма входящего события целиком связывается с одним долгом. Перераспределение одного поступления между несколькими основаниями не реализовано, как указано в ТЗ.
- Сессия разбора сохраняет не более трёх рекомендованных карточек. Остальные вопросы доступны через `mode=all`; откладывание не влияет на деньги. Текстовая модель по умолчанию выключена; опциональный HTTP-адаптер принимает только очищенный текст и требует отдельного согласия в запросе. Детерминированные категории применяются по словарю и явно сохранённым правилам.
- Правила категорий сопоставляются с точным описанием без учёта регистра и влияют только на будущий импорт. Автоматическое предложение групп погашений в текущем backend не реализовано. При зависимых погашениях undo требует явного `cascade=true`, затем отменяет все связи атомарно.
- Демо загружается в текущую базу лишь по явному вызову. Для изоляции от реальных данных используйте отдельную PostgreSQL БД/Compose-проект. Дата `today=2026-09-30` передаётся недельной сводке явно.
