# Передача backend-работы — состояние на 2026-09-20

Оценка готовности **backend по TZ.md: около 85%**. Это инженерная оценка, а не полная приёмка всех пунктов ТЗ. Фронтенд намеренно не создавался: его будет делать другой исполнитель.

## Что уже готово

- FastAPI-приложение в `backend/app`, PostgreSQL 16, версионированные SQL-миграции `backend/migrations/001–004`, `compose.yaml`, Dockerfile, закреплённые зависимости `backend/requirements.lock`.
- API импорта CSV: UTF-8/BOM/CP1251, разделители `,` и `;`, сопоставление заголовков и сохраняемые профили, preview без финансовой записи, подтверждение, лимит 10 MB/10 000 строк, понятные ошибки строк, дубли по ID и fingerprint/счётчику, ключ идемпотентности, coverage.
- Неизменные банковские записи, движения, экономические события, эффекты и долги в целых копейках. Поддержаны собственные переводы с парой/без пары, доход, расход, выдача и частичное погашение долга, совместная покупка и компенсации, возврат покупки, снятие и ручная наличная покупка, неразобранное поступление. Проверки остатка долга, предела возврата и суммы долей находятся на сервере.
- Ревизии финансовых событий, идемпотентные команды, журнал решений и отмена; `cascade=true` отменяет зависимые погашения атомарно. Категории и явно создаваемые правила точного описания. Аналитика по датам, категориям, неделям и предыдущему периоду; отдельные неопределённые суммы и предупреждения покрытия.
- Очередь вопросов, сохранённая сессия с максимум тремя рекомендациями, откладывание, кандидаты погашений/возвратов, групповое подтверждение компенсаций. Недельная сводка и отметка просмотра.
- Опциональная текстовая модель: `disabled` по умолчанию, `mock`, настраиваемый HTTPS JSON endpoint, серверный ключ, согласие, кэш, фоновая обработка максимум 20 описаний после импорта. Ответ модели не меняет финансовые факты. Статус доступен через API импорта.
- Синтетические `demo.csv`, `demo-first.csv`, `demo-second.csv`, независимые контрольные значения, генератор и скрипт подтверждения демо. Ключевые ответы типизированы в OpenAPI. Инструкции в `README.md` и `docs/DEMO.md`.

## Что реально проверено

- `python -m compileall -q backend` — успешно.
- `docker compose config --quiet` — успешно.
- 8 тестов `backend/tests` на PostgreSQL — успешно (1 предупреждение о deprecated alias в зависимости Starlette). Интеграционный тест использует отдельную временную схему, проверяет 69 строк, перекрытие импортов 37+32+0, профиль колонок, пары своих счетов, долг, ресторан, возврат, наличные, суммы сентября и недель, ограничения, undo и `mock` модели.
- Генератор демоданных воспроизвёл все три CSV побайтно.
- `docker compose up -d --build` — успешно; `/health` отвечает `ok`, `/openapi.json` доступен.
- 8 тестов внутри итогового API-контейнера на отдельной тестовой БД — успешно (то же предупреждение Starlette). Одноразовая тестовая БД после проверки удалена.
- `docker compose exec -T api python scripts/resolve_demo.py` — успешно дважды; оба запуска вернули сентябрьские `expenses_minor=860000`, `income_minor=2200000`, `net_minor=1340000`, `unresolved_incoming_minor=50000`.

## Что осталось для полной приёмки backend по ТЗ

1. Доработать очередь вопросов: сервер сейчас ранжирует в основном по сумме влияния и выдаёт кандидатов, но не собирает четыре компенсации ресторана в одну рекомендованную карточку и не восстанавливает отложенный вопрос при существенном изменении основания. Сделать устойчивые группировки/сигнатуры и тесты бюджета внимания.
2. Прогнать 1000/10000 строк и зафиксировать время. Проверить конкурентные импорты и команды под нагрузкой; сейчас есть транзакции, ограничения БД и advisory locks для импорта, но отдельного нагрузочного теста нет.
3. Проверить реальный HTTP-провайдер модели на конкретном выбранном сервисе и описать его точный формат. Сейчас адаптер универсальный JSON, автоматическое фоновое обогащение и `mock` проверены, внешний сервис не вызывался.
4. Дополнить типизированные схемы ответов для второстепенных API (`accounts`, `questions`, `weekly-review`, `rules`) и документировать примеры ошибок для фронтенда. Основные импорт, аналитика, события и решения уже типизированы.

## Среда и продолжение

Временный тестовый контейнер `blasy-test-db` остановлен и удалён. Одноразовая тестовая БД внутри Compose удалена. Код не закоммичен. Изменения видны в `git status`; чужих исходных файлов, кроме пустого README и `.gitignore`, в репозитории не было. Перед продолжением прочитать `TZ.md`, `README.md`, `docs/DECISIONS.md`, затем запустить тесты. Фронтенду передать `/openapi.json`, README и этот документ; суммы в API — копейки, даты включительные.
